# キーワード管理機能 設計書 (Keyword Management Design)

## 1. 概要 (Overview)

登録されたブックマークに「キーワード（タグ）」を付与し、それに基づいた分類、検索、および一括操作を可能にする機能です。ユーザーは特定のコンテキスト（例：「開発」「ニュース」「調査中」など）に関連する複数のブックマークを迅速に特定し、効率的にアクセスできることを目的とします。

## 2. コア・バリュー (Core Values)

- **高速なアクセス**: 特定のキーワードに関連するブックマークを瞬時に一覧表示し、一括で開くことができる。
- **共有可能な状態**: 選択されたキーワードの状態を URL に反映し、特定のフィルタリング結果をブックマーク（ブラウザ保存）可能にする。
- **軽快な操作感**: データは初回アクセス時に全件取得し、以降のフィルタリングはクライアントサイドで完結させることで、サーバー通信による待ち時間を排除する。

## 3. UI/UX 設計 (UI/UX Design)

### 3.1 画面構成とルーティング (Pages & Routing)

`react-router-dom` を使用し、以下の 3 つの主要画面を提供します。

#### 1. メイン一覧画面 (`/`)

- キーワードによるフィルタリングと、ブックマークのクイック起動を行うための中心的な画面。
- クエリパラメータ `?keywordId=...` に連動して、メモリ上の全件データから条件に合致するブックマークを瞬時に表示。
- キーワード未選択時は、全ブックマークあるいは最近使用した項目を表示。

#### 2. ブックマーク編集画面 (`/bookmark/[id]`)

- 特定のブックマークの詳細情報およびキーワードとの関連付けを管理する画面。
- **構成**:
  - 上部: 基本情報編集（現状の `BookmarkDetail` コンポーネントを活用）。
  - 中部: 「関連付け済みキーワード」セクション（チップ形式、クリックで紐付け解除）。
  - 下部: 「未関連付けのキーワード」セクション（リスト形式、クリックで紐付け追加）。
  - 新規作成: 新しいキーワードをその場で作成・適用する機能。

#### 3. キーワード詳細画面 (`/keyword/[id]`)

- 特定のキーワードに属するブックマークの管理およびキーワード自体の編集を行う画面。
- **構成**:
  - 上部: キーワード名の編集・削除。
  - 中部: 「関連付け済みブックマーク」セクション（一括起動ボタン付き）。
  - 下部: 「未関連付けのブックマーク」セクション（検索・選択による紐付け追加）。

### 3.2 特徴的な操作 (Core Interactions)

- **相互管理**: ブックマーク側からも、キーワード側からも、双方向に関連付けを直感的に操作可能。
- **一括操作**: キーワード詳細画面やサイドバーから、関連する全ブックマークを 1 クリックで別タブ起動。
- **リンク共有**: 特定のキーワードやブックマークの状態が URL に反映されるため、特定の管理ビューを直接開くことが可能。
- **AND 検索**: サイドバーで複数のキーワードを選択した場合、すべてに関連付けられたブックマークのみを抽出して表示する。選択状態はトグル（クリックで選択/解除）で管理される。

## 4. データモデル (Data Model)

### 4.1 データベース (SQLite / Drizzle ORM)

- **`keywords` テーブル**: キーワード自体の情報を保持。
  - `keyword_id`: integer (PK)
  - `keyword_name`: text (Unique)
- **`bookmark_keywords` テーブル**: 多対多のリレーションを管理。
  - `bookmark_id`: integer (FK)
  - `keyword_id`: integer (FK)
  - 複合ユニーク制約: `(bookmark_id, keyword_id)`

### 4.2 API 仕様 (Hono)

- **`GET /api/bookmarks` (拡張)**
  - レスポンスに各ブックマークに紐付く `keywords: { id, name }[]` を含める。
- **`PATCH /api/bookmarks/:id` (拡張)**
  - リクエストボディでキーワード ID の配列を受け取り、紐付けを更新する。
- **`GET /api/keywords` (新規)**
  - 全キーワードの一覧と、関連するブックマーク件数を取得。

## 5. フロントエンド実装戦略 (Frontend Implementation)

### 5.1 状態管理 (React Query)

- ブックマークおよびキーワードデータをキャッシュとして保持。
- `staleTime` を長めに設定し、URL 遷移に伴う再フェッチを抑制。

### 5.2 フィルタリングロジック

- URL の `searchParams` を監視し、メモリ上の全件データから該当するブックマークをフィルタリングして表示コンポーネントに渡す。

### 5.3 保存と同期のタイミング

- 詳細画面における情報の変更（基本情報およびキーワードの関連付け）は、一律で「保存（更新）」ボタンの押下によって確定される。
- 保存成功後、React Query のキャッシュを更新（Invalidate）し、メイン一覧画面やサイドバーに即座に変更を反映させる。

### 5.4 将来の拡張性と最適化 (Scalability)

※ 初期実装ではシンプルさを優先し、以下の対応はデータ量が増大した段階で検討する。

- **インクリメンタル検索**: 「未関連付け」リストが膨大になることを想定し、それぞれのセクションにインライン検索バーを設置する。
- **仮想スクロール**: 大量表示時のレンダリング負荷を軽減するため、リスト表示に仮想スクロールを導入する。
- **パフォーマンス**: 全件取得のサイズが数MBを超える場合、一部のデータを遅延読み込み（Lazy Load）する構成へ移行する。

## 6. 実装ステップ (Roadmap)

1. **Step 1 (Backend)**: API の拡張。ブックマーク・キーワードの相互取得および紐付け更新エンドポイントの実装。
2. **Step 2 (Frontend)**: `react-router-dom` の導入とページ定義（`/`, `/bookmark/:id`, `/keyword/:id`）の作成。
3. **Step 3 (UI)**: メイン一覧画面のローカルフィルタリングとキーワードサイドバーの実装。
4. **Step 4 (UI)**: ブックマーク編集画面 (`/bookmark/:id`) の双方向関連付け UI 実装。
5. **Step 5 (UI)**: キーワード詳細画面 (`/keyword/:id`) の双方向関連付け UI 実装。
6. **Step 6 (Function)**: 「一括で開く」機能の全体統合。
